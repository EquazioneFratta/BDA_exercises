================================================================================
  Outlier Detection for Gearbox Readings
  Problem 3
================================================================================

--------------------------------------------------------------------------------
0. DATASET – HOW TO DOWNLOAD
--------------------------------------------------------------------------------

The dataset used is the "Gearbox Fault Detection Dataset – PHM 2009 NASA",
publicly available on Kaggle at:

  https://www.kaggle.com/datasets/hetarthchopra/gearbox-fault-detection-dataset-phm-2009-nasa

It can be downloaded programmatically using the kagglehub library:

  import kagglehub
  path = kagglehub.dataset_download(
      "hetarthchopra/gearbox-fault-detection-dataset-phm-2009-nasa"
  )
  print("Path to dataset files:", path)

After download, place all CSV files under:
  data/gearbox-fault-detection-dataset-phm-2009-nasa/

in the same directory as the scripts.

--------------------------------------------------------------------------------
1. HOW TO RUN
--------------------------------------------------------------------------------

The solution consists of two scripts:

  runKMeans.py   – main Spark job (outlier detection)
  plot.py        – local visualisation script (run after the Spark job)

Step 1 – On IRIS HPC, submit the Spark job:

  sbatch run_gearbox.sh

Step 2 – Results are written to results.out.

Step 3 – After the job finishes, copy the sample CSV back locally.

Step 4 – Generate the plot locally:

  python plot.py

  This produces gearbox_clusters_pca.png.

4. CODE EXPLANATION
--------------------------------------------------------------------------------

---- 4a. runKMeans.py -------------------------------------------------------

This is the main PySpark script submitted to the IRIS cluster via spark-submit.
It performs the following steps in order:

  1. IMPORTS AND OPTIONAL LIBRARIES
     Standard libraries (math, numpy, os, time) are always imported.
     matplotlib and sklearn are imported inside a try/except block so that the
     script does not crash on HPC where those packages are unavailable. A boolean
     flag (VIZ_AVAILABLE) controls which visualisation path is taken later.

  2. SPARK SESSION
     A SparkSession is created with the application name
     "GearboxOutlierDetection". The SparkContext (sc) is extracted from it.

  3. DATA LOADING
     All CSV files matching the glob pattern are loaded with sc.textFile().
     Each line is parsed by parse_line(), which splits on commas, converts the
     three fields to floats, and wraps them in a pyspark.mllib.linalg.Vectors
     dense vector. Lines that do not have exactly 3 valid floats (e.g., empty
     lines or header artefacts) are filtered out. The resulting RDD is cached so
     Spark does not re-read the files on every action.

  4. NORMALISATION
     The normalize() function computes per-feature z-score statistics (mean and
     standard deviation) in a single distributed pass over the data using
     reduce() and aggregate(). It returns a closure (normalize_vector) that maps
     any raw vector to its normalised equivalent. The normalised RDD is cached
     and materialised before the main loop so that normalisation time is not
     charged to the first k iteration.

  5. DISTANCE HELPERS
     distance(a, b) computes the Euclidean distance between two numpy arrays.
     distToCentroid(vector, model) predicts the cluster for a given vector and
     returns its distance to the corresponding centroid.

  6. OUTLIER DETECTION LOOP (k = 2 to 12)
     For each value of k:
       - KMeans.train() fits a K-Means model on the normalised RDD.
       - Cluster sizes are computed with a map-reduceByKey.
       - Each original (non-normalised) data point is scored by applying
         normalize_func on the fly and computing distToCentroid. The 25 points
         with the largest distances are returned by takeOrdered() and printed.
     Runtimes are recorded with time.time() for each sub-step and printed
     immediately (flush=True) so they appear live in the .out file.

  7. VISUALISATION
     A 0.1% random sample of the normalised data is collected to the driver.
     If matplotlib and sklearn are available: PCA reduces the 3D data
     to 2D and a scatter plot coloured by cluster is saved as PNG.
     If not available: the sample is written to gearbox_k12.csv
     for offline plotting with plot.py.

  8. CLEANUP
     Both cached RDDs are unpersisted and the SparkSession is stopped cleanly.

---- 4b. plot.py --------------------------------------------------------

This lightweight local script is run on a personal machine after copying
gearbox_k12.csv from the cluster. It does not require Spark.

  1. Reads the CSV into a pandas DataFrame (columns: vib_hs, vib_ls, speed,
     cluster).

  2. PCA 2-D PLOT: sklearn's PCA reduces the 3 sensor dimensions to 2 principal
     components. A matplotlib scatter plot coloured by cluster ID is saved as
     gearbox_clusters_pca.png.

  3. DIRECT 3-D SCATTER: since the gearbox data has exactly 3 features, no
     dimensionality reduction is needed for a 3-D view. A second plot using
     mpl_toolkits.mplot3d places the three sensor channels directly on the X, Y,
     and Z axes, and is saved as gearbox_clusters_3d.png.


---- NOTE ON .py vs .ipynb FORMAT ----------------------------------------------

Due to technical constraints encountered during development — in particular,
several module compatibility issues on the IRIS cluster that required
significant debugging time — we worked directly with standalone .py scripts
rather than notebooks. This made iterative testing and spark-submit submission
considerably easier, as a notebook would need to be converted to .py via
nbconvert anyway before it could be run on the cluster. This is the reason why
only .py scripts are included in this folder.
