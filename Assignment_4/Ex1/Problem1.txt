Observation: The clustering coefficient is 0 because the graph built from
edges.csv is bipartite (heroes on one side, comics on the other). Bipartite
graphs cannot contain triangles by definition, so triangleCount() returns 0
for every vertex and the clustering coefficient is trivially 0. A meaningful
clustering coefficient would require analysing the projected hero-hero graph
(e.g. using hero-network.csv).

Graph characterisation: The Marvel graph is sparse. The degree distribution
is heavily skewed — while the mean degree is 9.75, the standard deviation of
37.23 and maximum of 1577 indicate that a small number of high-degree hubs
(heroes appearing in very many comics, or comics featuring very many heroes)
coexist with a large majority of low-degree nodes. Despite this sparsity, the
average path length of 4.3 is short relative to the graph size, consistent
with the small-world property commonly observed in real social networks. Note
that the average path length is an estimate based on a 1% random sample of
source vertices. The long tail of the path-length histogram (pairs reaching
up to length 29) corresponds to vertices in the smaller isolated components
that are only loosely connected to the giant component.

Observation: The two ranking methods produce strikingly different results for
heroes. The degree ranking identifies well-known central characters (Captain
America, Iron Man, Thor, Hulk) who appear across hundreds of comics, which
aligns with expectations. The PageRank hero ranking instead surfaces 25 minor
characters all tied at the same low score of 0.8005, indicating they each
appear exclusively in one single highly-ranked comic and inherit its PageRank
without having broad connectivity of their own. This is a known artifact of
running PageRank on a bipartite graph, where rank flows from heroes to comics
and back, making isolated heroes in popular comics score deceptively high.
For comics, the overlap between the two methods is small but non-zero (3/25):
IW 1, IW 3 and MX '01 appear in both lists, confirming these are genuinely
central issues both by raw number of heroes featured and by network influence.
Overall, degree is a more reliable indicator of raw popularity in this
bipartite setting, while PageRank is better suited to a projected hero-hero
or comic-comic graph.

mismatches between the two files.

Main prompt used
----------------

I need to solve a graph analysis problem in Apache Spark using GraphX and Scala, based on the
"Marvel Universe Social Network" dataset from Kaggle, consisting of three CSV files: edges.csv
(hero, comic), nodes.csv (node, type), and hero-network.csv (hero1, hero2).

The solution must be a single Scala script for spark-shell in batch mode via stdin redirection.
Please add a time() helper wrapping each task and printing wall-clock runtimes. Prefix all
output with the task label [a], [b], etc. Follow the style of the attached RunGraphX.scala
reference script.

Task (a): Parse edges.csv into (hero, comic) pairs, derive all distinct vertex names, assign
Long IDs via zipWithUniqueId(), and build a Graph[String, Int]. Compare vertex sets with
nodes.csv using subtract() in both directions and report the differences.

Task (b): Run connectedComponents() and report the number of components and top-10 by size.

Task (c): Compute degree distribution with summary stats and top-10 vertices. Compute average
clustering coefficient via triangleCount() on an undirected copy of the graph. Provide average
path length via Pregel SSSP on a 1% vertex sample using the mergeMaps/updateState/sendMessages
pattern from the reference script, and print the path-length histogram.

Task (d): Run pageRank(0.001, 0.15) and report top-25 heroes and comics separately, using type
information from nodes.csv. Also rank by total degree using fullOuterJoin of inDegrees and
outDegrees, joined to vertices via standard RDD join (not VertexRDD innerJoin). Report overlap
between PageRank and degree top-25 lists for both heroes and comics.

Task (e): Derive hero co-occurrence pairs from edges.csv via groupByKey() and combinations.
Compare with hero-network.csv after stripping quotes, using subtract() in both directions.
Report counts of pairs in common, only in the derived set, and only in hero-network.csv.
